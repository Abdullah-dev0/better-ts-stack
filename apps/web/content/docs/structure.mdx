## Overview

The layout of a generated project depends on the options you select. This page shows the file tree for common combinations. Choosing [GitHub Actions CI](/docs/usage#github-actions-ci) also adds `.github/workflows/ci.yml` to any of them, and every project gets [AI agent instructions](/docs/usage#ai-agent-instructions) in `AGENTS.md` and `CLAUDE.md` unless you pass `--no-agents`. [VS Code settings](/docs/usage#vs-code-settings) add `.vscode/`.

`better-ts-stack.json` that records the options it was generated with.

## Monorepo

`--monorepo` puts each app in its own folder. Each one has the same layout as the single projects above, with its own `package.json`, `tsconfig.json`, `.env`, and ESLint config. The root only holds the workspace files.

<Files>
  <Folder name="my-app" defaultOpen>
    <Folder name="apps" defaultOpen>
      <Folder name="web">
        <File name="next.config.ts" />
        <File name="package.json" />
      </Folder>
      <Folder name="api">
        <File name="src/index.ts" />
        <File name="package.json" />
      </Folder>
    </Folder>
    <File name="package.json" />
    <File name="turbo.json" />
    <File name="README.md" />
    <File name="better-ts-stack.json" />
  </Folder>
</Files>

The root `package.json` lists the workspaces (pnpm uses `pnpm-workspace.yaml` instead) and runs `dev`, `build`, `start`, `lint`, and `type:check` in every app through Turborepo. `apps/api` is left out with `--api none`. See [Monorepo](/docs/modules/monorepo).

## Key file descriptions

### Backend

| File                            | Purpose                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------- |
| `src/index.ts`                  | Entry point. Configures Express, mounts routes, starts the server                                 |
| `src/env.ts`                    | Validates environment variables with Zod at startup                                               |
| `src/middleware/rateLimit.ts`   | Request limits, with `--rate-limit`                                                               |
| `src/routes/health.ts`          | `GET /health` endpoint                                                                            |
| `src/lib/prisma.ts`             | Prisma client singleton                                                                           |
| `src/lib/db.ts`                 | Mongoose connection helper                                                                        |
| `src/lib/auth.ts`               | Better Auth server, mounted on `/api/auth`                                                        |
| `src/lib/email.ts`              | Sends verification and password reset emails                                                      |
| `src/middleware/requireAuth.ts` | Requires a session (cookie or bearer token)                                                       |
| `src/routes/me.ts`              | `GET /api/me`, an example of a protected route                                                    |
| `src/routes/chat.ts`            | `POST /api/chat`, the streaming AI chat route, with `--ai`. NestJS: `src/chat/chat.controller.ts` |
| `prisma/schema.prisma`          | Prisma schema. Edit it to add your models                                                         |

## Environment variables

Variables are written to `.env.example` (and `.env`) based on selected modules.

### Backend base

```bash
PORT=3000
CORS_ORIGIN=*
```

### With PostgreSQL (Prisma or Drizzle)

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/postgres?schema=public"
```

### + MongoDB (Mongoose)

```bash
MONGODB_URI="mongodb://localhost:27017/myapp"
```

### With Better Auth

```bash
BETTER_AUTH_SECRET=please-change-me-to-a-random-string
BETTER_AUTH_URL=http://localhost:3000
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
RESEND_API_KEY=
EMAIL_FROM=onboarding@resend.dev
```

<Callout type="warn">
  The CLI creates both `.env` and `.env.example`. Replace placeholder values in
  `.env`, such as database URLs, before starting the server. Never commit `.env`
  to git.
</Callout>
