## How the CLI Works

Run the command, answer the prompts, and the CLI generates a project from your answers. Every prompt also has a flag, so scripts and CI can run it without prompts.

<Callout type="info">Run `npx better-ts-stack` and follow the prompts.</Callout>

---

## Flags

```bash
better-ts-stack [project-path] [options]
```

Options you leave out are asked interactively, unless you pass `--yes`.

```bash
# No prompts at all
npx better-ts-stack my-api --framework nestjs --database prisma --auth --yes

# Create the project in the current (empty) directory
npx better-ts-stack . --framework nextjs --database drizzle --pm pnpm

# Check the result without writing anything
npx better-ts-stack my-api --framework express --yes --dry-run
```

| Flag                         | Values                                       |
| ---------------------------- | -------------------------------------------- |
| `--framework <name>`         | `express`, `nestjs`, `nextjs`, `tanstack`    |
| `--database <name>`          | `none`, `prisma`, `drizzle`, `mongoose`      |
| `--pm <name>`                | `npm`, `pnpm`, `bun`                         |
| `--auth` / `--no-auth`       | Add authentication                           |
| `--docker` / `--no-docker`   | Add Docker files                             |
| `--git` / `--no-git`         | Initialize a git repository                  |
| `--install` / `--no-install` | Install dependencies                         |
| `-y`, `--yes`                | Use defaults for missing options, no prompts |
| `--dry-run`                  | Show the summary without writing files       |
| `-h`, `--help`               | Show help                                    |
| `-v`, `--version`            | Show the version                             |

`--database` names the ORM, which also selects the database: `prisma` and `drizzle` use PostgreSQL, `mongoose` uses MongoDB.

With `--yes`, the defaults are Express, no database, no auth, no Docker, npm, git initialized, and dependencies not installed.

`--auth` with `nextjs` or `tanstack` needs a database, because Better Auth stores users and sessions. Without one the CLI stops with an error.

`--yes` requires a project path.

## Prompt Flow

<Steps>

<Step>
### Intro

The CLI prints its name and version, then starts the prompts.

</Step>

<Step>
### Project name

```
? Project name:
  my-awesome-project
```

You can enter a name (`my-api`), a nested path (`apps/api`), or `.` to use the current directory. The target directory must be empty or not exist yet.

**Rules for the folder name**, which becomes the `package.json` name:

- Lowercase letters, numbers, and hyphens only
- Cannot be empty and cannot start or end with a hyphen

**Valid examples:** `my-api`, `cool-app-v2`, `apps/customer-portal`

</Step>

<Step>
### Application type

```
? Application type:
  (*) Backend API
  ( ) Full-stack
```

| Option          | What it generates                                     |
| --------------- | ----------------------------------------------------- |
| **Backend API** | Express or NestJS server (prompts for framework next) |
| **Full-stack**  | Next.js 16 or TanStack Start (prompts for framework)  |

<Callout type="info">
  **Full-stack** generates a single project at the root of your chosen
  directory, not a separate `backend/` + `frontend/` monorepo.
</Callout>
</Step>

<Step>
### Backend framework *(Backend API only)*

```
? Select a backend framework:
  (*) Express
  ( ) NestJS
```

| Option      | What it generates                                   |
| ----------- | --------------------------------------------------- |
| **Express** | Express 5 server, `tsx watch` for development       |
| **NestJS**  | NestJS 12 server (ES modules), `nest start --watch` |

> This prompt does **not** appear for Full-stack projects.

</Step>

<Step>
### Frontend framework *(Full-stack only)*

```
? Select a frontend framework:
  (*) Next.js 16 (App Router)
  ( ) TanStack Start (React)      (Release Candidate)
```

| Option             | What it generates                                      |
| ------------------ | ------------------------------------------------------ |
| **Next.js 16**     | App Router, `next dev`/`next build`, standalone server |
| **TanStack Start** | File-based routing, `vite dev`, served by `srvx`       |

</Step>

<Step>
### Database type

```
? Select a database:
  (*) none
  ( ) postgresql
  ( ) mongodb
```

| Choice         | Availability                      |
| -------------- | --------------------------------- |
| **none**       | Backend and Full-stack            |
| **PostgreSQL** | Backend and Full-stack            |
| **MongoDB**    | Backend and full-stack (Mongoose) |

</Step>

<Step>
### ORM / ODM *(shown only when a database is selected)*

For **PostgreSQL**:

```
? Select an ORM for postgresql:
  (*) prisma
  ( ) drizzle
```

| ORM     | Available in                                                  |
| ------- | ------------------------------------------------------------- |
| Prisma  | Backend (Express) and Full-stack (Next.js and TanStack Start) |
| Drizzle | Backend (Express) and Full-stack (Next.js and TanStack Start) |

For **MongoDB**:

```
? Select an ORM for mongodb:
  (*) Mongoose (MongoDB ODM)
```

| ODM      | Notes                          |
| -------- | ------------------------------ |
| Mongoose | Express, Next.js, and TanStack |

> If you select **none** for database type, this prompt is skipped entirely.

</Step>

<Step>
### Package manager

```
? Select a package manager:
  (*) npm
  ( ) pnpm
  ( ) bun
```

The generated `dev` script and install commands are tailored to your choice. With `bun`, the `dev` script uses `bun --watch` instead of `tsx watch`.

With `pnpm`, the CLI also writes `pnpm-workspace.yaml`. It holds the dependency overrides and approves the install scripts of `bcrypt`, `esbuild`, `prisma`, `@prisma/engines`, and `unrs-resolver`. Without that approval, pnpm 11 and later stop `pnpm install` with an "Ignored build scripts" error.

</Step>

<Step>
### Docker

```
? Use Docker?
  ( ) yes  (*) no
```

If yes, three files are added: `Dockerfile`, `docker-compose.yml`, and `.dockerignore`.

</Step>

<Step>
### Authentication

```
? Add authentication?      # Express
? Add Better Auth?         # Next.js / TanStack Start
  ( ) Yes  (*) No
```

**Express backend** - JWT-based auth with `jsonwebtoken` and `bcrypt`. Always prompted regardless of database selection.

**Next.js / TanStack full-stack** - Better Auth with a database adapter. **This prompt only appears if you selected a database.** If you chose `none` for database, auth is skipped automatically.

</Step>

<Step>
### Git initialization

```
? Initialize a git repository?
  (*) yes  ( ) no
```

If yes, the CLI runs `git init` after generating the project files. It does not create a commit, so commit the files yourself when you are ready.

</Step>

<Step>
### Install dependencies

```
? Install dependencies now?
  ( ) yes  (*) no
```

If yes, the CLI runs your chosen package manager's install command after generating the project.

</Step>

<Step>
### Confirmation summary

Before generating, the CLI displays a summary box:

```
Project    my-awesome-api
Directory  my-awesome-api
Stack      express · prisma · auth
Setup      npm · git

? Create this project?
  (*) Yes  ( ) No
```

Select **Yes** to start generation, or **No** to cancel without making changes.

</Step>

<Step>
### Generation and next steps

The CLI generates your project based on your selections, then optionally installs dependencies and initializes git.

On success you will see output similar to:

```bash
cd my-awesome-api
npm install        # if you skipped dependency install
npm run dev
```

</Step>

</Steps>

## After Generation

### Scripts - Backend (Express)

```bash
npm run dev        # tsx watch src/index.ts (hot reload, NODE_ENV=development)
npm run build      # tsc (compile TypeScript to dist/)
npm run start      # node dist/index.js (NODE_ENV=production)
npm run lint       # eslint src
npm run format     # prettier --write "src/**/*.ts"
npm run type:check # tsc --noEmit
```

With database (Prisma):

```bash
npm run prisma:generate
npm run prisma:migrate
npm run prisma:studio
```

With database (Mongoose): no additional scripts - connection is handled in `src/lib/db.ts`.

With Docker:

```bash
npm run docker:build
npm run docker:up
npm run docker:down
npm run docker:logs
```

### Scripts - Full-stack (Next.js)

```bash
npm run dev    # next dev
npm run build  # next build
npm run start  # next start
npm run lint   # eslint
```

### Scripts - Full-stack (TanStack Start)

```bash
npm run dev         # vite dev
npm run build       # vite build (dist/server/server.js + dist/client)
npm run start       # srvx --prod -s ../client dist/server/server.js
npm run type:check  # tsc --noEmit
npm run lint        # eslint src
```

With database (Prisma):

```bash
npm run prisma:generate
npm run prisma:migrate
npm run prisma:studio
```

With database (Drizzle):

```bash
npm run db:generate
npm run db:migrate
npm run db:studio
```

## Tips

- The project name becomes the folder name and the `package.json` name.
- Check `.env` before starting the server. Replace placeholder values such as database URLs with your own.
- All generated files are plain TypeScript, so you can edit them freely.

<Callout type="info">
  The generated code is a starting point. Review and test it before you deploy.
</Callout>
